## Finding

A name substitution cannot repair the writer. The new thread is an identity-scoped, versioned, source-linked cross-platform context object, while the old insert was a platform/thread-key aggregate.

The minimum current-schema write crosses these relations in one transaction:

1. `working.first_party_context_thread` requires `context_thread_id`, `owner_person_id`, `matter_id`, and `court_case_id`. The owner and case are foreign keys to `registry.person` and the paired `registry.court_case(id, matter_id)`.
2. `working.first_party_context_thread_version` requires a version ordinal, classifier ID/version, 32-byte assertion digest, confidence, review state, exact first/last message bounds, and the greatest required source availability. Its deferred validator rejects versions without message membership, incorrect bounds, or incorrect horizon availability.
3. `working.first_party_context_thread_message` requires message membership and a unique ordinal for that version. `working.first_party_context_thread_source` requires an existing `context.source_version`, source anchor ordinal, platform/key, representation/capture/format, perspective person, metadata provenance and review state, assertion version, 32-byte provenance digest, and asserter. Its required source availability must agree with coverage time.
4. The existing `working.message` insert also uses a fresh random ID, but the snapshot requires `working.message.id` to reference the *same* `working.normalized_record.id`. Its `conversation_id` is not a substitute for the cross-platform context-thread version and membership relationship.

No current code in this call chain supplies the missing values.
