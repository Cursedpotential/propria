Cross-platform engine identity and validation contract

Status: owner-approved requirement, recorded 2026-09-12. Implementation and platform certification are pending.

This decision applies to every external extraction engine. The first required pair is Poppler because Windows is the development/test and desktop-control environment while Linux is the production worker environment. The two builds are separate test subjects:

  • poppler-windows-amd64
  • poppler-linux-amd64

A pass on either profile is not evidence that the other profile passes. Differences in Poppler version, compilation, linked libraries, fonts, executable layout, locale, or command behavior can change extraction output.

Required profile record

FieldRequirement

Engine ID and versionCanonical family ID (poppler) and version obtained from the exact executable under test. Version is data, not inferred from a download filename.
Operating system and architectureNormalized OS (windows or linux) and architecture (amd64), plus the raw values reported by the runtime.
Executable hashSHA-256 of every executable actually invoked. The primary pdftotext hash is mandatory.
Full resolved pathCanonical absolute path observed by the worker at execution time. No unresolved environment variable, relative path, PATH-only name, or guessed production path.
CapabilitiesDeclared operations and formats from the engine manifest, including at minimum PDF extract_text for the first Poppler profile.
Exact command invokedExecutable plus ordered argument vector exactly as executed. Also retain a rendered display string, working directory, relevant locale/environment overrides, exit code, stdout hash, and stderr hash.
Extraction checksEvery check name, expected value/range, observed value, status, explanation, and associated output hash. A single aggregate passed: true is insufficient.

Normative run-record shape

The registry describes what may run. A run record proves what did run. The extraction package must preserve the run record (or an immutable content-addressed snapshot of it), so a later registry edit cannot rewrite history.

The fixture must be identified by SHA-256 before execution; matching a filename alone is not enough. The input evidence remains immutable. Test output and scratch files go to the lane's controlled runtime area on Windows or the designated worker scratch area on Linux.

The Poppler text-engine check covers its own output. The later complete PDF extraction package also has an independent raw-content-stream channel for text runs invisible to normal extractors, including the documented Love you plus four-glyph run. That package-level requirement must not be misreported as a capability of pdftotext alone.

For cross-platform comparison, retain hashes of raw bytes and of a separately labelled normalized-text view. Normalization may standardize BOM and newline representation for comparison, but it must not fold Unicode characters, replace glyphs, trim content, or overwrite the raw output.

Acceptance and failure rules

  1. Resolve the executable, calculate SHA-256, query its version, and validate the input fixture hash before invoking extraction.
  2. Run the same frozen fixture and check definitions independently on both platforms.
  3. Fail the profile on a missing executable, hash/version mismatch, timeout, nonzero exit, malformed output, failed check, or incomplete provenance. Never silently select a PATH fallback.
  4. Preserve each platform result even when results disagree. A mismatch opens a review item; it is not normalized away.
  5. Write the profile ID and immutable run-record identity into every extraction package and later derived record that depends on its output.
  6. Do not promote either profile from pending until its own target environment has executed the exact reference artifact and all required fields and checks are populated.

Phase impact

  • Phase 0 closure: the v3 Poppler bake-off remains open until the pinned Windows profile is tested. The existing Go/PE/ELF receipt is still valid for the earlier skeleton scope.
  • Phase 1 engine registry: registry and doctor output must expose profile ID, platform, resolved path, version, hash, capabilities, and certification status—not only a language-neutral engine name.
  • Production readiness: the Linux VPS profile is the deployment gate even if the Windows development profile passes first. Production must not silently fall back to corpus-scale local execution.
  • Extraction packages: package provenance records the actual engine profile and run, enabling reproducibility, comparison, deduplication, and later lakehouse audit.
