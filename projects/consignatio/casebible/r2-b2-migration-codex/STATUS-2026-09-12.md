# R2 to B2 migration status — 2026-09-12

## Canonical scope

- Source corpus: all occurrences recorded across the three legacy R2 buckets.
- Destination: `b2:salem-data/consignatio/vault/v1/`.
- Physical payload deduplication is authorized only by verified SHA-256 identity or the frozen, conflict-free `(MD5, byte size) -> SHA-256` bridge.
- Every source occurrence and its original bucket/path remains in the lake catalog even when many occurrences share one physical payload.
- Legacy path labels such as `junk`, `quarantine`, `dupe`, `to_be_deleted`, and `.review_hold` are untrusted metadata and never migration exclusions.
- Alternate formats, exports, screenshots, and independently recovered copies remain distinct corroborating occurrences unless byte identity is actually proven.

## Verified baseline

- PG18 inventory: 1,279,556 occurrences across `casebible-raw`, `casebible-sorted`, and `casebible-quarantine`.
- Inventory SHA-256: `41dee727a3737d634420acc0202abfc29dcb7c93504de854d9a0afaec1173ff0`.
- Valid `(MD5, byte size)` groups: 337,067, totaling 1,114,709,222,228 bytes (about 1.01 TiB).
- Rows without a usable inventory MD5: 79, totaling 274,247,900,317 bytes. These remain held for conservative source-identity handling and are not silently discarded.
- Restricted B2 canary passed; the B2 key cannot delete objects and is scoped to `consignatio/vault/v1/`.

  - Fixed at two readers to preserve Windows `V:`/`Y:` mount responsiveness.

## Code and validation

- Manifest builder: 12/12 tests pass locally and on the VPS.
- Payload runtime: 24/24 tests pass locally and on the VPS.
- Exporter validates gzip integrity, JSON schema/digest shape, record counts, and SHA-256 sidecars before a partition is accepted.
- Payload runtime uses an isolated Unix-domain rclone RC socket, immutable `copyfile`, bounded workers/memory, append-only outcome ledgers, and separate `copied_unverified` versus `verified` states.
- No R2 inventory listing job is currently competing with the local mounts.
