Stage by stage

📥 Sources

The owner's real evidence, mixed-format. Messaging spans raw structured (SMS-XML, FB DYI JSON) and derived (transcript TXT/CSV, tabular CSV, PDF, XLSX) plus Snapchat JSON and phone logs. Canonical structured formats live in casebible-raw; derived views are secondary.

🟦 SORT — raw → sorted

Dedup (md5 pre-filter → sha256 canonical), type-first vault, best-format selection (structured > derived), quarantine junk, enrich tags. One writer, one reader (PROCESS, read-only).

🟩 1 · Custody spine de-risked

sha256 = the one identity. Write-once blob to the /data store. 3-level SHA-256: file hash → per-message hash → hash-linked chain (verifies). Ed25519 signing = phase-2; RFC-3161 external timestamp = recommended anchor.

🟩 2 · Parse owner-custom built, deploy pending

Registry picks the parser by content-sniff (not extension): sms_xml / SBV-primary, facebook_json, imessage_html (static-DOM + script-embedded regex + silent-empty hard-fail), transcript-marker, messaging_csv, snapchat, xlsx, extract.text/OCR. Per-message records; speakers never blended.

🟩 3 · Store live

analysis.normalized_record in Postgres — the relational source of truth. Survives Milvus resets (bind-mount). The 1,918 provisional iMessage rows live here now.

🟩 4 · Knowledge

Embed (bge-m3, 1024-d) → Milvus casebible_evidence + PG knowledge contents. Milvus now fault-isolated on its own stack.

🟩 5 · Graph ADR-0031

Entities / relationships / timeline → Graphiti (Neo4j, group_id=casebible). This is the lane that needs Graphiti wired into the Agno agents.

🚪 Gateway & access facade live

facade :8090 (11 tools, registry_ok:true) → ContextForge single MCP gateway → Agno agents. SBV viewer :8085 for view + open-file + manual-process (routes back through custody).

🖥️ Unified control & viewing surface planned — design starting

From the original iterations: a single web surface to view, tweak, change, and monitor everything — evidence rows, the pipeline stages and jobs, the DBs (PG/Neo4j/Milvus/Surreal), the agents, and the custody chain. Today these are scattered across separate tools (AgentOS UI, SBV viewer, Attu for Milvus, ContextForge admin). The plan consolidates them into one pane of glass. PIPELINE is being asked to mine the original-iteration design intent and propose the architecture (extend AgentOS UI vs. a dedicated dashboard) before building.
